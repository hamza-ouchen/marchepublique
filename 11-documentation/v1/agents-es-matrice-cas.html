5. Les cas d'usage expliqués

CAS ALe run quotidien — de 6h00 à 8h00 (qui fait quoi, dans l'ordre)

6h00
RÉGISSEUR le cron appelle FastAPI POST /cron/run → ouverture du run : run_logs = « ouvert »
6h05
INSPECTEUR rechercher_avis → extraction → écrire tenders → rapport au RÉGISSEUR (132 avis, 3 rejetés)
6h20
COMPAGNON 2 lectures massives → calcul Match /100 → écrire scores + écrire digests
7h00
JUGE lit les scores au-dessus du seuil → 4 contrôles → écrire verdicts (tableau, un objet par offre)
7h30
COMPAGNON finalise les digests → whatsapp.envoyer → statut « envoyé »
8h00
le client lit son digest · HITL 2 si À ÉTUDIER : décision humaine dans le dashboard
18h00
RÉGISSEUR clôture le run → rapport dans 08-observabilite
🔑 Après chaque étape, le contrôle revient au RÉGISSEUR — les agents rendent leur rapport et s'arrêtent. Le RÉGISSEUR ne transporte jamais les données : elles vivent dans la base.

CAS BL'exécution manuelle par l'admin

Le même workflow, déclenché par un humain : bouton dashboard → POST /run (token admin) → RÉGISSEUR. Utilisé après un incident ou un ajout. Le déclencheur change, pas le pilote : mêmes étapes, même tracé, mêmes HITL.

CAS C« Quelles offres cette semaine ? » — demandé sur WhatsApp

1
le client écrit sur WhatsApp → FastAPI /webhook → RÉGISSEUR classe : consultation
2
Aucun appel à l'INSPECTEUR — CONCIERGE lit scores + verdicts de la semaine (RLS company_id)
3
CONCIERGE répond : top 3 + verdicts + fraicheur: "données du 17-11 08:00" + lien vers la fiche complète
{ "langue": "ar", "reponse": {
    "texte": "هاد الأسبوع عندك 3 فرص قوية: … 🟢 Match 96 — GO … 🟡 Match 81 — À ÉTUDIER",
    "fraicheur": "données du 17-11-2026 08:00" } }
🔑 Collecte ≠ consultation : INSPECTEUR collecte une fois par jour (6h00 / run admin) ; la consultation est instantanée, toute la journée, depuis la base. Avant 8h00 : dernières données connues + « l'update arrive à 8h00 ».

CAS DClic « consulter » sur une offre — la fiche dossier

Le clic ouvre le dossier déjà calculé : GET /dossiers/{ref} → base → affichage. Aucun agent n'est appelé — la consultation est un affichage, pas un recalcul :

📄 2026/DTR/0123 · Match 96/100 (algo 1.0.0)
   secteur 35/35 ✓ · région 20/20 ✓ · capacité 20/20 ✓ · qualifications 15/15 ✓ · historique 6/10 ✗
   ⚖️ GO — justification : décret 2-22-431, art. 12 · 📚 sources : portail + décret

CAS E« Comment gagner cette offre ? » — accompagnement & ligne rouge

CONCIERGE explique le dossier déjà calculé : points forts, points perdus, les 3 risques à vérifier — avec citation. Aucune nouvelle collecte, aucun recalcul.

🚫 Ligne rouge (jamais, dans aucun cas) : écrire la soumission du client · promettre un gain · appeler quiconque · garantir un résultat. → refus poli + HITL 3 (« je vérifie et je reviens vers vous » → validation humaine).

CAS FLe JUGE : objet vs tableau

FormeQuand
Objet (1 verdict)fiche d'une seule offre (dashboard) · réexamen demandé par le RÉGISSEUR
Tableau (lot)run du matin — un objet par offre retenue
🔑 risques_a_verifier (≥ 3) n'apparaît que pour À ÉTUDIER — jamais pour GO ni NO-GO.

CAS GLe portail est en panne — le mode dégradé

INSPECTEUR : rechercher_avis échoue 2× → RÉGISSEUR bascule sur source: "secours" (jeu de secours) + état « dégradé » → le digest part quand même avant 8h00, avec bandeau d'alerte. Jamais de silence client.

CAS HQuestion hors périmètre — l'escalade HITL 3

« Rédigez-moi ma soumission complète » → CONCIERGE refuse poliment → RÉGISSEUR crée l'escalade → HITL 3 un humain valide (ou traite) la réponse avant envoi. Les 3 points HITL du BPMN : HITL 1 confirmation du profil · HITL 2 décision sur À ÉTUDIER · HITL 3 escalade hors périmètre.

6. Les 6 règles transversales (à répéter à l'équipe)

#Règle
1Tout passe par le RÉGISSEUR — aucun agent ne parle à un autre directement ; chacun rend son rapport et s'arrête.
2Les données passent par la base, pas par les agents — le contrôle (signaux, routage) circule via le RÉGISSEUR ; les données métier circulent via la base, en batch.
3Collecte ≠ consultation — le portail n'est appelé que par l'INSPECTEUR (6h00 / run admin) ; les questions des clients lisent la base en quelques secondes.
4On calcule une fois par jour, on consulte toute la journée — même entrée = même sortie (Match déterministe, versionné).
5Listé = autorisé, non listé = interdit — la matrice §3 fait partie du contrat de chaque agent.
6On prépare, on ne promet pas — JUGE et CONCIERGE expliquent et justifient ; toute action engageante est refusée et remontée à un humain (HITL).
